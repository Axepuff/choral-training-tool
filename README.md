# Хор · Репетиция

Мобильное веб-приложение на React 19, строгом TypeScript и Vite 8. Обычный CSS
и CSS Modules, без UI-кита. React выбран вместо Preact с разрешения пользователя:
нативный Preact framework Storybook пока не генерирует манифест API для MCP.

## Продолжение разработки

Этап дизайна завершён. Приложение сейчас работает на моках; следующий этап — Go backend
и подключение реальных данных/аудио. Начинайте новую задачу с [AGENTS.md](AGENTS.md).

## Локальный запуск

Установите Node.js 24 LTS. Распакуйте архив и откройте терминал в папке проекта:

```sh
npm ci
npm run dev
```

Откройте в браузере на этом же компьютере адрес `http://127.0.0.1:5173`.
Для Storybook откройте второй терминал в той же папке:

```sh
npm run storybook
```

Откройте `http://127.0.0.1:6006`. Это адреса для локального запуска, не ссылки
на облачную машину. Облачная среда Codex для работы с проектом не нужна.

## Что реализовано

- Общие компоненты и стили для приложения и Storybook.
- Токены цветов, типографики, отступов и скруглений: `src/styles/tokens.css`.
- Светлый интерфейс от 360 px, области касания минимум 44 × 44 px.
- TrackControls: громкость, взаимоисключающие Solo/Mute, состояние загрузки.
  Включение Mute отключает Solo и наоборот; можно выбрать несколько Solo-партий.
- Плеер: четыре голоса и минус, цветные волны на одном таймлайне с сеткой тактов 4/4, курсор,
  верхний play/pause, перемотка, возврат к началу, повтор тактов 2–3, визуальный метроном.
  Компактный микшер: пять партий в ряд, кнопки S/M и вертикальные фейдеры.
- 34 stories компонентов и страниц; интерактивные состояния содержат `play`-проверки.
- Отдельная story «16 тактов · горизонтальная прокрутка»: волны и сетка прокручиваются вместе, курсор остаётся видимым при воспроизведении.
- Story «Мобильный · горизонтально · 16 тактов»: при повороте телефона таймлайн занимает всю ширину, S/M размещаются рядом с вертикальными фейдерами.
- Viewport-пресеты: 360, 390, 768 и 1280 px.

Плеер работает на детерминированных моках и таймере, без звука. Аудиодвижок,
запись, реальная авторизация, серверная загрузка файлов и backend не реализованы.
Формы входа/создания и локальный выбор файлов уже есть. Будущий backend — Go.

## Проверки и сборка

```sh
npm run typecheck
npm run lint
npm run build
npm run build-storybook
```

Результаты сборок: `dist/` и `storybook-static/`. `npm run preview` запускает
собранное приложение на порту 4173. Сборка Storybook сама по себе не выполняет
`play`-проверки: они выполняются при открытии соответствующих stories.

## Просмотр через GitHub Pages

Workflow `.github/workflows/storybook-pages.yml` проверяет и публикует Storybook
при каждом push в `main`. Его также можно запустить вручную из вкладки Actions
(workflow **Publish Storybook**, кнопка **Run workflow**).

При первой настройке в репозитории GitHub выберите **Settings → Pages →
Build and deployment → Source → GitHub Actions**. Затем запустите workflow.
Для публикации используются стандартные разрешения `GITHUB_TOKEN`, отдельный
секрет в репозитории не нужен. Права записи Pages выданы только заданию deploy.

После успешного задания deploy адрес сайта появится в GitHub Environment
`github-pages` и в Settings → Pages. Ожидаемый адрес для этого репозитория:
`https://axepuff.github.io/choral-training-tool/`.
Публикуется статическая сборка Storybook; установка Node.js на компьютере
зрителя не нужна. Компоненты и документация на этом сайте общедоступны.
Сервер MCP на Pages не запускается: для него используется dev-сервер ниже.

## Официальный Storybook MCP и Codex

Storybook и официальный `@storybook/addon-mcp` закреплены на стабильной версии
10.6.2. Предварительные npm-релизы не нужны, однако AI API Storybook официально
имеет статус **preview** и может изменяться.

В `.storybook/main.ts` включены addon и `componentsManifest`.
При запущенном `npm run storybook` сервер MCP доступен по адресу
`http://127.0.0.1:6006/mcp` через Streamable HTTP. Статическая сборка его не запускает.

Проектная конфигурация Codex находится в `.codex/config.toml`; Codex читает её
в доверенном проекте. Альтернативная регистрация через CLI:

```sh
codex mcp add choral_storybook --url http://127.0.0.1:6006/mcp
codex mcp get choral_storybook --json
```

После регистрации запустите новую сессию Codex из папки проекта, оставив
Storybook работающим. Попросите агента вызвать `docs-list`, затем `docs-show`
с `id: "components-track-controls"`. Codex CLI 0.159.2 поддерживает этот транспорт.
Сам запуск Storybook или наличие конфигурации не доказывают подключение агента.

Проверка реального MCP-протокола без дополнительных зависимостей:

```sh
npm run check:mcp
```

Скрипт выполняет `initialize`, `tools/list`, `docs-list`, `docs-show`, проверяет
наличие обоих компонентов и свойств TrackControls. При ошибке завершается
с ненулевым кодом. Эти запросы проверены из облачного агента. Динамическое появление
MCP-инструментов в текущем облачном чате не подтверждено; локальная конфигурация
CLI не гарантирует её поддержку облачным клиентом. Новую локальную сессию нужно
проверить приведёнными выше вызовами.

Инструменты MCP для тестирования требуют отдельного Vitest-addon; он не установлен.
Для этой задачи используются инструменты документации и браузерные `play`-проверки.

Документация: [Storybook MCP](https://storybook.js.org/docs/ai/mcp/overview),
[поддержка framework](https://github.com/storybookjs/storybook/blob/v10.6.2/docs/ai/mcp/overview.mdx#framework-support),
[Codex MCP](https://developers.openai.com/codex/mcp/).

В облачной песочнице при недоступном домашнем npm-кеше можно использовать:
`npm ci --cache /tmp/choral-npm-cache --no-audit --no-fund`.

### Создание песни (макет)

В приложении откройте `/?page=create-song`; в Storybook — «Страницы → Создание песни».
Форма: название, BPM (20–300), размер (1–32 доли; длительность 1/1–1/32),
1–32 трека с названиями и локальным выбором файлов, заметки до 1000 символов.
Пять stories показывают пустую/заполненную форму, мобильный вариант, выбранные
файлы и отсутствие файлов. Кнопка создания проверяет форму, но ничего не сохраняет.

Файловый диалог намеренно не ограничен MIME/расширением: браузерная поддержка
декодирования не должна ограничивать будущий серверный импорт. FFmpeg на Go backend
пока не подключён. План: проверять реальное содержимое и доступный декодер на сервере,
конвертировать в целевой формат, проверить результат и сохранить его; только затем
удалять оригинал. Набор поддерживаемых форматов зависит от сборки FFmpeg; размеры,
длительности, целевой формат и обработку ошибок нужно определить при реализации backend.
Сейчас файлы хранятся только в памяти страницы, при её закрытии выбор теряется.

### Вход (макет)

`/?page=sign-in`, Storybook — «Страницы → Вход». Email, пароль, показ/скрытие пароля,
состояния проверки, неверных данных и ошибки соединения. Передачи данных и реального
входа пока нет. Согласованные роли, публичные ссылки и план серверной сессии описаны
в [docs/authentication.md](docs/authentication.md).

### Список песен (макет)

`/?page=library`, Storybook — «Страницы → Список песен». Поиск по названию, сортировка,
создание песни, переход в демонстрационный плеер и копирование демо-ссылки.
Заголовок списка — «Песни». Гость видит опубликованные записи только для просмотра;
преподаватель — свои и опубликованные, редактирует свои; администратор — все и владельцев. Эти ограничения
в UI иллюстративные: настоящую проверку прав выполняет будущий Go backend.
Список статический, новые песни пока не сохраняются; демо-ссылки не являются
защищёнными токенами и не реализуют отзыв доступа. Состояния: мобильный, админ,
пустой список, поиск без результатов, интерактивный поиск/сортировка,
общий список только для просмотра и редактирование с сохранением в памяти макета.
Кнопка «Ссылка на список» копирует `/?page=library&list=choir-demo`; она открывает
гостевой режим и не передаёт права редактора.

Публикация Pages включает сам макет приложения в `/app/` рядом со Storybook.
Общий список: `https://axepuff.github.io/choral-training-tool/app/?page=library&list=choir-demo`.
После обеих сборок команда `node scripts/assemble-pages.mjs` добавляет приложение
в артефакт Storybook; workflow выполняет её автоматически. Ссылки из Storybook
на песню/создание и копируемые ссылки ведут в этот предпросмотр приложения.
При локальной проверке опубликованной структуры соберите оба проекта, выполните
эту команду и обслуживайте `storybook-static` обычным статическим HTTP-сервером.

Мобильный список использует компактные строки: название открывает плеер, справа
иконки редактирования и ссылки, области касания 44 × 44 px. Поиск и сортировка
расположены в одну строку. Кнопки создания и ссылки на список доступны только
преподавателю/администратору. Story «Длинный список · 360 px» показывает 16 песен
и перенос длинного названия.
