# Проверка статусов и захвата фейдера — Issue #75

## Объём

Windows, Edge headless через CDP, 8 ноября 2026. Изолированная рабочая копия
от main d59756d. Источник первоначального дефекта — сообщение владельца
и снимок реального iPhone. Дефект пропуска касаний Safari здесь не воспроизведён;
расширение нативной ручки проверено в Chromium, не на физическом устройстве.

## Реальный ввод

- Regression owner: tests/e2e/storybook.mjs, ui-rangeslider--faders.
  Захват на 20 px правее и 16 px ниже центра ручки: на прежнем CSS значение
  скачет с 60 на 42 при нажатии, проверка падает; с прямоугольной областью 44 px
  сохраняется 60, последующее перетаскивание меняет громкость. Соседний muted
  фейдер действительно controlled, его значение остаётся 60.
- CDP touch: крайние значения 0/100 доступны. Edge при touchstart перемещает
  ручку к позиции касания и до, и после исправления; это не доказательство
  устранения исходных промахов iPhone.
- Нативная клавиатура Home/End даёт 0/100, ArrowDown после End даёт 99.
- Disabled показан отдельно; runtime unavailable tracks блокирует все фейдеры.
- Enter открывает расшифровку индикатора, Escape закрывает; story проверяет
  нажатие и «Закрыть». Предупреждение о недоступной волне сохраняет готовность
  аудио: существующая проверка startsWith('Готово') не изменена.

## Визуальная матрица

Stories layouts-rehearsal-player--three-tracks,
layouts-rehearsal-player--unavailable-tracks и
компоненты-состояние-дорожки--states просмотрены при 320×640, 360×800, 800×360,
1280×900. Проверены отсутствие переполнения страницы, компактный круг фейдера,
отступы индикатора внутри канала, disabled, видимый focus, расшифровка ошибки
в границах viewport. Все пять статусов представлены одной story; отдельный
runtime story использует реальные состояния useAudio при отсутствующих media.
Готовность в demo не подменяет сетевой runtime.

## Проверки и ограничения

TypeScript, целевой ESLint, git diff --check; ограниченная сборка TrackStatus и
RangeSlider и runner (3/3 stories). Дополнительная runtime story выполнена через
dev Storybook во всех четырёх размерах. Полные frontend/audio/backend/e2e suites
локально не повторялись; автоматический CI проверяется отдельно в PR.
Физические iPhone/Android, Safari и Firefox локально не проверены. Production
не менялся. Артефакты локального просмотра не являются опубликованным preview.

Первый PR CI выявил старые селекторы small[role=status] в audio browser: они
обновлены на доступность управления громкостью и role=status внутри партии,
с сохранением проверки 32 готовых/31 исправных дорожек и восстановления после
ошибки аудиоустройства. Повтор этой полной проверки делегирован CI нового head.
