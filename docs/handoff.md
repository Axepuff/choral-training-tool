## Принятые UX-решения

- React разрешён пользователем вместо Preact ради совместимости Storybook MCP.
- Светлый компактный mobile-first UI. На страницах один отступ, без серой внешней
  рамки и без шапок «Хор / Демо», «Библиотека хора / Макет».
- Все inputs/select/textarea имеют `id`/`name`; стрелки select с отступом от края.
- Не должно быть общего горизонтального скролла страницы. Таймлайн скроллится
  горизонтально сам, свайпом; сохранены клавиатура/трекпад.
- Solo жёлтый; S и M у одной партии не могут быть включены одновременно.
  Включение последней S из всех дорожек сбрасывает все Solo.
- Минус в общей волне очень тусклый, без заливки. Цветных точек-легенд у названий
  и заголовков «Партии / Громкость · Solo · Mute» нет.
- В списке одна компактная строка: название открывает плеер, справа иконки
  редактирования/ссылки. Поиск и сортировка — одна строка. Обычная строка около 65 px,
  touch targets 44 × 44 px. Есть проверка длинного списка и длинных названий.
- Заголовок — «Песни», без «Мои». Гость может искать/сортировать/открывать
  опубликованные песни; создание, редактирование и ссылка на список — только редакторам.
- Для прослушивания по ссылке регистрация не нужна. Учитель редактирует свои
  песни, админ — все. См. [схему доступа](authentication.md).

## Чего ещё нет и на что обратить внимание

- Нет Go-модуля, БД, миграций, API, настоящей авторизации и аккаунтов.
- Нет серверной загрузки, конвертации, файлового хранилища, очереди обработки,
  отдачи аудио и резервного копирования.
- Нет реального многодорожечного воспроизведения. `MockTrack.id` ограничен пятью
  голосами; будущая модель обязана поддерживать произвольные ID и число дорожек.
- BPM/размер в плеере пока фиксированы демо-моделью. Реальные значения из формы,
  различная длина файлов и фактическая длительность ещё не интегрированы.
- Повтор включается только для тактов 2–3. Выбор начала/конца отсутствует;
  пользователь уже заметил этот пробел. В roadmap выделена отдельная задача.
- При перезагрузке/переходе между страницами изменения макета теряются.
- Существующие файлы в форме редактирования представлены именами-заглушками.
- Демо-параметры `song`/`list` предсказуемы и не защищают данные. Нужны настоящие
  токены, область действия, отзыв и серверная проверка каждого запроса.
- Роль и владелец в списке — props и строки, а не идентичность из сессии.
- Текущая форма: BPM 20–300; числитель размера 1–32; знаменатель 1/2/4/8/16/32;
  треков 1–32; название песни до 160, дорожки до 80, заметки до 1000 символов.
  Контракт должен согласовать Unicode-подсчёт/валидацию с Go, не копировать слепо `.length`.
- Приём широкого спектра файлов не означает поддержку всех кодеков: её определит
  сборка FFmpeg. Оригинал удаляется после успешной конвертации и фиксации результата.

## Что проверялось

Перед передачей были успешно выполнены frontend typecheck/lint, сборки приложения
и Storybook, браузерные `play`-проверки **34 stories**, проверки мобильных размеров,
landscape, длинных названий, управления, локального редактирования и гостевых ссылок.
Это исторические результаты этапа UI, не результат тестирования будущего backend.
34 stories: TrackControls 5, плеер 7, создание 5, вход 7, список 10.

MCP проверялся настоящими протокольными запросами `initialize`, `tools/list`,
`docs-list`, `docs-show`. Динамическая активация инструмента в текущем облачном чате
не подтверждена. Конфигурация CLI или обычный запуск Storybook не доказывают её.

В среде на дату передачи: Node 24.19.0, npm 11.9.0, FFmpeg 7.1.5. Компилятор Go
не подтверждён: `/usr/bin/go version` отвечает `Unknown option: version`.
Установка и закрепление настоящего Go toolchain включены в задачу backend foundation.

Следующие действия и зависимости — в [roadmap](roadmap.md).
