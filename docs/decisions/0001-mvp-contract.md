# ADR 0001: контракт первой рабочей версии

Статус: принят для реализации после ревью PR Issue #2. Дата: 2026-10-19.
Нормативная HTTP-схема: [`../api/openapi.yaml`](../api/openapi.yaml). Правила, которые
не выражаются в OpenAPI (транзакции, права, обработка), — в
[`../api/README.md`](../api/README.md).

## Решение

- Один Go-процесс обслуживает `/api/v1` и собранный frontend на одном HTTPS origin.
  SQLite и каталог с файлами находятся на постоянном томе. Worker работает в том же
  сервисе и восстанавливает задания из SQLite после рестарта. Отдельного брокера нет.
  Для `database/sql` выбран pure Go `modernc.org/sqlite`, WAL, `foreign_keys=ON`
  на каждом соединении, `busy_timeout=5000` ms и один writer. Миграции —
  последовательные SQL-файлы с таблицей `schema_migrations` и транзакцией на
  миграцию. Точные версии Go/модулей закрепляет Issue #3 при создании `backend/`.
- Сервер генерирует неизменяемые UUIDv4 для всех сущностей. `owner_id` записывается
  из сессии либо явно проверяется для администратора; клиент не может назначить
  владельца песни. Целочисленная `version` песни защищает полную замену метаданных
  через `If-Match`; создание песни и загрузка принимают `Idempotency-Key`.
- Песня начинается как `draft`. `published` разрешён лишь когда у каждой дорожки
  есть проверенный активный playback asset. Состояние `ready` вычисляется из активных
  assets и не подменяет публикацию. Ожидающая замена не выключает текущий asset.
- Публичный список — динамический каталог **одного владельца**: все его
  `published` песни с `ready=true` на момент запроса. У каждой ссылки свой токен;
  song-ссылка открывает только одну песню. Участник получает только чтение.
  Учитель управляет ссылками для своих песен/каталога, администратор — для любых.
- Токен ссылки — 32 криптографически случайных байта в base64url без padding
  (43 символа). В БД хранится только SHA-256 токена. При перевыпуске старый hash
  атомарно заменяется; выключение одной ссылки не затрагивает другие. В URL и
  HTTP-логах токен редактируется/не записывается. Отключение не отзывает байты,
  уже полученные браузером.
- Аудио для браузера: AAC-LC в MP4/M4A, mono, 48 kHz, 96 kbit/s, без loudness
  normalization и выравнивания по первой ноте. Каждый файл начинается в общей
  точке 0; padding/encoder delay должен быть учтён при проверке. Время хранится
  целыми миллисекундами. Длина песни — максимум длительностей активных дорожек,
  короткие дорожки после окончания дают тишину. Дорожки разной длины допустимы.
  Плеер синхронизирует декодированные источники с одним AudioContext clock.
- Импорт ограничен 100 MiB и 20 минутами на файл; после фактической проверки
  FFprobe/FFmpeg, а не по расширению. Probe ≤15 секунд, обработка ≤5 минут wall
  time, одновременно ≤2 задания на сервер и ≤1 на песню, до 2 повторов после
  временного сбоя. Неподдерживаемый кодек и повреждённый файл дают стабильную
  ошибку без удаления оригинала. FFmpeg запускается argv, без shell.
  Базовая сборка FFmpeg/FFprobe — 7.1.x с AAC encoder; при старте worker
  проверяет наличие encoder/decoder. Версии binary фиксируются в Issue #3/#8.
- Сессия: случайный 32-byte ID, в БД только hash, абсолютный срок 7 суток без
  продления. Cookie `__Host-choral_session`: `Secure; HttpOnly; SameSite=Lax;
  Path=/`, без `Domain`. Вход/смена пароля ротируют сессию. Изменяющие запросы
  требуют same-origin `Origin`; при cookie-сессии также `X-CSRF-Token` из
  `/auth/me`. Вход дополнительно принимает только JSON и same-origin Origin.
- Первый admin создаётся локальной одноразовой командой bootstrap с паролем из
  защищённого stdin, только если пользователей ещё нет; повторный вызов не меняет
  записи. Администратор задаёт временный пароль пользователя вне приложения,
  сбрасывает его через API, что отзывает сессии и требует смены при следующем
  входе. Локальный `reset-admin` восстанавливает доступ единственного admin.
  Argon2id: 64 MiB, 3 прохода, parallelism 1, salt 16 B, hash 32 B.
  Публичной регистрации и email-восстановления нет.

## Причины и последствия

Один origin упрощает cookie и аудио Range-запросы. UUIDv4 проще реализовать без
дополнительной библиотеки. Динамический список не требует отдельной сущности
playlist и не показывает черновики. Полная замена метаданных с версией даёт
предсказуемые конфликты для двух редакторов. AAC-LC в MP4 работает в целевых
современных браузерах, но качество синхронизации и декодирование 32 дорожек
нужно проверить на реальных устройствах в задачах audio/player. Нет обещания
приёма любого формата: точная поддержка определяется сборкой FFmpeg.

Если измерения на iOS/Android выявят неточный sample alignment или превышение
памяти, формат и способ доставки меняются отдельным ADR с версией API/asset,
а не молча в worker. Ни исходники, ни недоверенные имена файлов не становятся
публичными путями.
