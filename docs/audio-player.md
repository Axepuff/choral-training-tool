# Синхронный плеер — Issue #11

Runtime public song/list, название песни в личном списке и «Слушать песню» в сохранённой песне используют настоящие
media URLs, gain, BPM/размер, durationMs и peaks из Go API. Историческое описание
мок-плеера в handoff относится к этапу дизайна. Stories/Pages demo сохраняют явно
демонстрационный таймер; runtime на него при ошибках не переключается.

## Движок и границы

`src/audio/engine.ts` использует браузерный Web Audio без новых зависимостей.
Один AudioContext, один scheduled start для всех AudioBufferSourceNode, отдельный
GainNode каждой дорожки. Pause сохраняет позицию context.currentTime, seek/resume
пересоздают одноразовые source nodes с общим временем старта и offset. RAF только
читает audio clock для курсора. После конца короткой дорожки — тишина. Gain меняется
с коротким сглаживанием; Solo/Mute взаимоисключаются, все Solo сбрасываются.

Загрузка последовательная; кнопка старта ждёт завершения попыток всех дорожек.
Ошибка файла не блокирует готовые дорожки, ошибка peaks не блокирует звук. Для
повтора неудачной загрузки обновите страницу. Число дорожек 1–32 и произвольные ID
задаёт серверный контракт. Общая сетка учитывает знаменатель размера и фактическую
длительность; короткая волна не растягивается до конца песни. Микшер и таймлайн
прокручиваются внутри своих областей, не растягивая страницу.

Выбран buffer-based Web Audio ради единого clock и точного планирования: независимые
HTMLAudioElement не дают такого старта. Это имеет явный предел памяти. Контекст
декодирует в 24 kHz (серверный playback mono), предел суммарных PCM buffers — 256 MiB;
проверка по metadata происходит до скачивания/декодирования очередного файла.
Одна максимальная дорожка 20 минут требует около 110 MiB. Если общий объём больше
лимита, соответствующие дорожки получают явную ошибку. Это **ограничение реализации**:
32 максимально длинных файла одновременно не поддержаны. Для этого нужен отдельный
streaming PCM/AudioWorklet pipeline с bounded ring buffers; независимые media clocks
не являются заменой синхронизации. Временная память декодера/сжатого файла и overhead
браузера существуют сверх лимита PCM. Серверные метаданные считаются доверенными.

Resume вызывается из кнопки до await; autoplay не используется. При блокировке
аудиоустройства показывается ошибка, можно нажать Play снова. Уход страницы в фон,
pagehide и unmount останавливают звук; unmount отменяет fetch, закрывает контекст,
освобождает buffers и connections. Поздний resume/decode после ухода не запускает
прошлую песню. Public media/peaks запросы отправляются с credentials=omit, session —
same-origin; redirect запрещён, URLs ограничены `/api/v1/`. Отзыв ссылки даёт ошибку
на новом запросе; уже загруженные байты отозвать нельзя.

Повтор и метроном runtime пока заблокированы с объясняющими title. Выбор диапазона,
реальный loop scheduling и метроном — #12. Демо фиксированных тактов 2–3 не выдаётся
за готовый runtime loop.

## Воспроизводимые проверки

```sh
node --test tests/audio.test.mjs
node tests/audio-browser.mjs
```

Первый тест использует управляемый clock: 32 стабильных ID, 20 циклов pause/resume/
seek, короткий файл, gain/solo/mute, all-solo reset, dispose и гонка resume/unmount.
Второй запускает Vite и headless Google Chrome через CDP; нужны установленный
`/usr/bin/google-chrome` и `ffmpeg`. Генерирует синтетический WAV вне Git, конвертирует
в настоящий AAC-LC mono 48 kHz 96 kbit/s и отдаёт контрактный fixture API локальным
HTTP server. Проверяет реальный decode/play после trusted mouse gesture, cursor/
pause/seek/resume и освобождение контекста при смене песни, 32 канала с отдельным 404, peaks, Solo, отсутствие public cookies и переполнения
при 320×640, 360×740, 740×360 и 1280×800. OfflineAudioContext дополнительно проверяет
нулевой output до общего старта и точное сложение двух сигналов на первом sample.
Fixture API используется только тестом; runtime требует настоящий Go backend.

Проверен локальный Linux Google Chrome 147.0.7727.116 headless. Это эмуляция размеров, **не проверка физических мобильных
устройств**. Safari/iOS, Chrome/Android и аппаратный audio output здесь не проверялись.
Перед выпуском проверить gesture, interruption/background, seek и 20-минутные песни
на реальных телефонах, а также непрерывную синхронизацию на длинной записи.
