# Постоянные ссылки — Issue #70

Основной сценарий — одна постоянная ссылка на репертуар владельца. Ученики
получают её один раз; опубликованные и готовые песни появляются по тому же
адресу при следующем открытии списка. Отдельная ссылка ведёт к одной песне.

## Интерфейс

В библиотеке главное действие — «Копировать ссылку для учеников», у каждой
доступной для редактирования песни — кнопка копирования её адреса. Преподаватель
работает со своим репертуаром. Администратор сначала явно выбирает аккаунт
в поле «Чей репертуар передать»; это не фильтр общего списка песен. Владелец
песенной ссылки определяется песней, независимо от этого выбора. Email берётся
из API; до загрузки владельца действие недоступно.

Открытие страницы или настроек ничего не создаёт. Первое явное копирование
создаёт постоянную ссылку, если её ещё нет и нет действующих старых ссылок.
Повторное копирование возвращает прежний адрес. Успех показывается рядом с
действием только после успешного Clipboard. При отказе, в том числе после
асинхронного запроса в Safari, открываются настройки с выделенным адресом,
отдельной кнопкой копирования и возможностью скопировать вручную.

Редактирование, копирование и меню песни остаются в одном ряду. На узком экране
этот ряд расположен под названием. Сообщение об успехе занимает отдельную строку
на всю ширину песни и переносится, не сужая название и не сдвигая кнопки.

Меню `⋯` открывает «Настройки ссылки». Общий `ShareActions` используется в
`LiveLibrary`, stories и `WorkflowPrototype`; отдельная нижняя панель удалена.
Нативный `dialog` расположен по центру desktop и у нижнего края телефона,
с собственной прокруткой при нехватке высоты. Он показывает название песни
или репертуара, email владельца, адрес и настоящий публичный предпросмотр.
Фокус удерживается внутри; Escape/закрытие возвращают его к вызвавшей кнопке
и сохраняют место в списке. В подтверждении фокус сначала на «Отмена».

Сохраняются Jost, светлая поверхность, оранжевое основное действие и мягкий
неоморфизм существующих UI-примитивов. Цвета, рельеф, расстояния и фон затемнения
берутся из общих tokens. Цели касания — минимум 44 × 44 px; длинные названия
переносятся, страница не скрывает overflow. Создание песни остаётся доступным
нейтральным действием, редкие операции ссылки отделены от копирования.

«Заменить адрес» и «Отключить ссылку» требуют подтверждения с точным контекстом.
Отмена не отправляет запрос. После замены доступен новый адрес; после отключения
обычное копирование открывает статус, а не включает доступ. Вернуть доступ можно
только явным «Создать новый адрес» — прежний адрес не оживает. При ошибке или
неопределённом результате UI перечитывает состояние без автоматического повтора
изменения. Ответ от прежнего выбора владельца не обновляет экран и Clipboard.

Публикация — отдельное действие: ссылка не публикует песню. Статус «Доступна
ученикам» соответствует `published && ready`. Для черновика/неготовой песни
настройки объясняют причину и дают перейти в редактор. Пустой репертуар может
иметь действующую ссылку; первая публикация не требует нового адреса. Поиск
по библиотеке не считается доказательством, что весь репертуар пуст.

Отключение song-ссылки не убирает песню из репертуара; отключение list-ссылки
не отзывает отдельные song-ссылки. Подтверждения прямо объясняют эту границу
и то, что другие ранее созданные адреса не изменятся. Полностью закрывает
публичный доступ к песне снятие публикации. Уже полученное браузером аудио
отозвать нельзя.

## API и состояния

Все маршруты ниже имеют префикс `/api/v1`. Источник схем —
[OpenAPI](api/openapi.yaml). `scope` — либо `{kind:"list",ownerId}`, либо
`{kind:"song",songId}`; поля двух областей не смешиваются.

| Операция | Результат |
| --- | --- |
| `GET /shares/permanent?kind=list&ownerId=…` либо `kind=song&songId=…` | `{current,legacy}`; чтение без создания |
| `POST /shares/permanent` с scope | Атомарное первое создание (`201`) или возврат того же адреса (`200`) |
| Текущая ссылка отключена | POST возвращает `409 share_disabled`; GET возвращает её с `url:null` |
| Постоянной ссылки нет, есть действующие старые | POST без явного `acceptLegacy:true` возвращает `409 legacy_transition_required` |
| `POST /shares/{id}/rotate` | Новый токен, включая явное создание адреса после отключения |
| `DELETE /shares/{id}` | Отключение только указанной ссылки |

`current` — `null` или `{share,version,url}`. Действующий URL относительный:
`/?list=<token>` либо `/?song=<token>`; браузер дополняет свой origin.
`legacy` содержит метаданные прежних выдач без их исходных URL. Отсутствие
постоянной записи, отключение и наличие старых ссылок — разные состояния.

Для rotate/delete постоянной записи нужен `If-Match: "<version>"`.
Отсутствующий заголовок даёт `428 precondition_required`, устаревший —
`412 precondition_failed`. Успешное изменение увеличивает version. Повтор
с прежней версией не выполняет вторую замену; клиент сначала читает фактическое
состояние. Legacy endpoints сохраняют прежние правила совместимости.

Владелец/admin проверяются сервером, как и действующая сессия в транзакции;
изменения требуют CSRF. Чужой song скрывается через 404, выбор чужого владельца
списка преподавателем даёт 403. Public routes сохраняют проверку token scope,
`published/ready`, текущих media и удалённых песен независимо от admin cookie.
Закрытые ответы не кешируются. Ошибки API не заменяются fixtures.

Для выбора владельца реализован только существующий read-only контракт
`GET /admin/users`: admin с обычным паролем, `limit=1..100` (по умолчанию 30),
email/id sort, снимок состава/порядка на 15 минут и актуальные поля аккаунтов
на каждой странице. Cursor зашифрован и привязан к admin и маршруту: подмена
или другой actor → 400, истечение/удаление подлинного снимка → 410. Cookie,
роль и блокировка перечитываются на каждом запросе. UI загружает все страницы;
создание/блокировка/смена ролей аккаунтов остаются за рамками #70 и относятся к #13.

## Хранение и переход

Миграция `0006_permanent_shares.sql` добавляет в `shares` поля `permanent`,
`version`, `token_ciphertext`, `token_nonce`. Частичные UNIQUE-индексы допускают
ровно одну постоянную запись на владельца списка и на песню, включая отключённую
запись. Транзакции и индексы защищают от дубликатов при повторе/конкуренции.

Случайный токен сохраняет прежний SHA-256 для публичной проверки. Для повторного
получения адреса добавлено AES-GCM шифрование существующим `share-responses.key`;
AAD связывает ciphertext с ID, видом, владельцем и песней. Это отдельное хранение,
которое не истекает вместе с 24-часовым replay. Повреждение/подмена ciphertext,
nonce или несовпадение hash даёт 503 без скрытого перевыпуска. Отключение очищает
ciphertext/nonce; явная замена записывает новый секрет и увеличивает версию.
Тот же key обслуживает account cursor с отдельным AAD для маршрута и actor.

Все старые строки получают `permanent=0`; их токены и статусы не меняются.
Исходный токен из hash восстановить нельзя, поэтому старые записи не назначаются
постоянной ссылкой автоматически. Если есть действующие legacy, пользователь
явно создаёт постоянную ссылку; старые продолжают работать. Отозванная история
сама по себе не мешает первому созданию. В свёрнутом разделе «Ранее созданные
ссылки» видны даты и статусы; действующие адреса можно отключать по одному
с подтверждением. Совместимый старый POST остаётся доступен API-клиентам,
но основной UI не создаёт дополнительные выдачи.

SQLite и `share-responses.key` должны вместе входить в защищённый backup.
После restore проверить и публичный доступ, и получение того же постоянного
адреса владельцем/admin. Действующий публичный hash сам по себе не доказывает
восстановление ключа. Не печатать токены, ключи и приватные URL в отчёты/логи.
Процедура backup/restore и proxy logging — в [operations.md](operations.md).

## Проверки

- Go sharing: сохранение адреса за пределами replay TTL и после restart,
  owner/admin/чужой/guest, конкурентное создание, If-Match, отключение/замена,
  публикация, legacy migration и отказ при подмене ciphertext.
- Go auth: admin-only UserPage, снимок/сортировка, restart/expiry и scope cursor,
  актуальные права/блокировка и отсутствие закрытых полей в DTO.
- Songs browser: настоящее HTTP/SQLite/FFmpeg приложение, копирование,
  подтверждение/отмена, отзыв/новый адрес, reload и одинаковый URL у owner/admin.
- Затронутые stories/play: общие settings, первый адрес, legacy, disabled,
  ошибка, пустое/неопубликованное, Clipboard fallback, потерянный ответ замены
  и запоздалый ответ старого владельца. Визуальная проверка 320/360,
  landscape/desktop, длинных заголовков,
  touch targets, фокуса и возврата после закрытия.

Результаты конкретного прогона записываются в PR. Эмуляция Chrome/Edge не
доказывает работу на физическом iPhone/Safari или Android. Контейнерный restore
и production rollout не следуют из локальных проверок.
